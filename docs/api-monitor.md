API 监控在普通版和 Debug 版中默认启用，从助手点击开启挑战或接管选卡/战斗起，持续到结算返回主界面。自然结束等待期间仍检查。进入助手暂停后立即关闭检查；恢复时先重新识别页面，再决定是否接管对战。浏览器在暂停期间发出的积压请求按实际发出时间过滤，不会在恢复后误判为新变化。

界面布局：顶部左侧为紧凑的挂机设置和按钮，顶部右侧为通用游戏参数及灰色十字分隔的四系设置，底部全部为日志。API 提示在日志中使用红色粗体，同时状态栏显示「API 变动，已暂停」。

基准文件为数据目录内的 `api_baseline.json`，通常与 EXE 同目录。EXE 内附一份默认基准，首次运行时导出；已有文件不会被覆盖。启动时读取，API 暂停后点击「恢复战斗」时再次读取。无效基准会使助手保持暂停，不会悄悄关闭检查。基准中各接口注明来自实际请求还是公开前端代码；本版使用 2026-10-30 的实测结算/选卡请求，以及前端已确认的切关、宝箱、任务与大厅数据刷新调用。

监控只观察 URL 路径含 `/actgame/` 的 HTTP 请求，不另外向服务器查询，也不安装新的游戏帧循环。比较项目如下：

| 项目 | 处理 |
| --- | --- |
| 域名、请求方法、完整接口路径 | 不在基准中即报告 |
| 查询参数、表单/JSON 请求体 | 新增字段即报告 |
| 内嵌 JSON，例如 `stat`、`logIdList`、`eventJson` | 解析后继续检查新增字段和数组中的对象字段 |
| 卡牌伤害表 | `{card_id}` 只匹配数字卡牌 ID，换阵容不会误报；增加其它属性仍会报告 |
| 伤害数值、血量、时间、字段缺省或减少、正常接口重复次数 | 不用于判断 API 变化 |
| 响应结构、请求头、WebSocket、其它 API 命名空间 | 不在本版检查范围 |

字段使用 JSON Pointer 风格路径，例如 `/stat/cardDmg/{card_id}`；`/logIdList/[]` 表示数组元素。基准是明确的允许字段列表，不会自动把新请求学习成正常请求。超过 256 KiB 或无法完整解析的请求也会暂停并报告，避免截断数据后漏掉新字段。

发生变化后，助手在下一个动作边界暂停：停止自动选卡、点击、回血、伤害强化、攻速和分系覆盖，卸载这些覆盖并交还原生逻辑。不会为了暂停而强制降血或冻结攻击；浏览器与已完成场数保留，游戏自身继续运行。暂停期间修改 GUI 参数只会保存待恢复设置。点击「恢复战斗」会重读基准并继续原任务；基准没有接受该变化时，下次遇到同样请求仍会暂停。

这属于请求监听，不是发送前拦截：首个异常请求可能已发送，不能撤回；卸载覆盖也不能撤销之前已经产生的伤害、回血、控制效果或服务端状态。

详细报告保存在 `logs/api_change_时间戳.json`，包含基准版本及 SHA-256、当前任务/关卡/已完成场数、触发接口、新增字段路径、该接口的允许字段、实际请求的脱敏结构与数值、前 16 条相关请求的字段结构，以及恢复原生逻辑是否成功。认证、身份信息不保留原文；若报告写入失败，会在日志明确提示，助手仍保持暂停。

验证包括新增/嵌套字段、未知路径/方法/域名、正常切关与宝箱变体、数字卡牌 ID、基准文件保留与损坏、暂停/恢复和计数保持。另通过本地 Chromium HTTP 请求验证了真实监听、撤销覆盖，以及浏览器暂停期间请求在恢复后不会误报。没有向真实游戏提交测试请求。
