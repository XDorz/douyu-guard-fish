# 保卫鱼娘 · 自动挂机助手

斗鱼直播间 H5 互动游戏「保卫鱼娘」的自动化工具。Windows 桌面 GUI + 免安装单文件 exe。

> 仅供学习研究使用。使用本工具可能违反平台用户协议，账号风险自负。

## 功能

- **自动挂机**：自动「开启挑战」→ 自动打完一整场 → 自动开下一场，用完每日 **10 次免费次数**自动停止
- **自动选技能**：开局"跳过 BOSS 关"技能三选一 + 战中每 5 关的三选一，按阵容（土系主力 + SR 猛犸象仔）智能评分挑选
- **血条自动回满**：战斗基地血量低于阈值（默认 5）时自动回满（朝满值 20 回血，本地运行时直改，免费）。开启后按用户设置的单场时限收尾；服务端拒绝对局时尝试正常结束，不以拒绝响应或关卡耗时直接判定结算
- **自动领宝箱**：战斗中宝箱随出随领，最上方进度宝箱弹窗关闭不会结束当前战斗，结算宝箱自动领取
- **秒杀策略**（可选，默认关）：支持全额秒杀、概率秒杀、攻击倍率和攻击力固定。都继续调用游戏原生伤害/击杀链路；攻击倍率放大命中伤害；固定模式临时设置各卡基础攻击力，仍受原生技能倍率和暴击影响
- **实时控制**：回血、伤害、攻速和分系覆盖可在战斗中切换。关闭某项时恢复对应原生方法；挂机期间保留轻量击杀监听。点「本场正常结束」会把基地降到 1 血，关闭强化与重复控制，持续压住新的攻击发射，并把在途伤害改成随机 1–100，等待游戏自己的失败/结算流程，下一场恢复原设置；「终止并退出」会强制关闭浏览器
- **全局攻速**：独立于伤害强化，可选倍率或固定攻击间隔；`-2` 倍表示原速的 1/2，`0` 表示原速。攻击间隔限制为 0.2–180 个游戏秒，保留原生目标和在途弹丸限制
- **分系设置**：日志右侧两行一组，雷/火/冰/风各自勾选生效，概率支持倍率或固定百分比，CD 始终固定。风系固定概率对所有风卡一致，CD 共享；雷/火/冰增加按卡计时的可选 CD
- **重复控制**：攻速旁的「冰可重复」「土可重复」独立开关，允许同一敌人本关再次受控；冰冻概率/CD 仍生效，关闭后保留原来的受控历史。土系原生没有概率判断，不提供虚构的概率字段
- **暂时停止 / 恢复战斗**：本场正常结算回到主界面后暂停所有助手轮询和操作，保留浏览器与运行计数。恢复从下一场接着打，例如 1/9 → 2/9；不会重头计数。
- **尽快完成**：每场开局后自动正常收尾，结算后按设置的场数继续。尚未发射弹丸的引擎先放行一次原生攻击更新，再暂停新攻击，收尾伤害为随机 1–100。
- **今日场次**：免费次数旁显示每日挑战任务的接口进度；任务口径为「发起挑战」。不会把助手本次完成场数当成今日场次；读取不到时显示「未读取」，另列服务端开战计数。
- **停滞恢复**：发射弹丸或实际击杀任一发生即重置四分钟倒计时；持续没有活动才刷新恢复。排除技能/奖励弹窗、收尾和正常攻击冷却，数据未识别时不猜测卡死。刷新后接回同一场；若回到大厅则记录中断、重试当前任务，不增加完成场数
- **结束条件**：可设置打到指定绝对关卡、从本场起始关推进指定关卡数、单场最长监控时间。两个关卡目标同时设置时取较大的实际关卡数；达到目标只结束当前场，成功结算后仍按「场数」继续。
- **自然结束宽限**：单场时限到点后使用上述收尾机制，最多主动等待 3 分钟，仍每 0.5 秒轮询。GUI 超时未结算会暂停助手并保留本场，点击恢复后继续监控，不计为完成；CLI 超时退出且不计为完成。原生冰冻/减速仍可能延长等待。
- **数据抓包**：所有游戏接口响应落盘 `logs/api_*.jsonl`；每场战报 `logs/battles_*.jsonl`（起始关/结束关/用时/技能选择/回血次数/秒杀次数/血量时间线）
- **单关耗时与杀敌**：通过关卡后输出用时和本关实际杀敌，保存在 `logs/stages_*.jsonl`，同时写入战报的 `stageTimes`。杀敌来自原生击杀入口，不把怪物抵达基地算成击杀；中途接管标注「已观测」
- **配置保存**：GUI 设置自动保存在数据目录的 `config.json`，普通版和 Debug 版共用，替换 EXE 后自动恢复。
- **安全红线**：**绝技、加速、技能刷新等一切需要鱼翅（付费）的功能一律不自动点击**；免费用尽后仅使用免费获取的**银币**续打（10 银币/局，余额不足自动停止）

## 快速开始（免安装）

1. 到 [最新 Release](https://github.com/XDorz/douyu-guard-fish/releases/latest) 直接下载 `guard-fish-assistant-v版本号-win64.exe`，无需解压
2. 运行下载的 EXE（需要诊断时选择带 `-debug-` 的 EXE）
3. 首次使用点「登录斗鱼」登录账号（登录态保存在本机 `chrome_profile/`，有效期约 7 天）
4. 填房间号（默认 `12306`）→ 点「开始挂机」

**运行要求**：Windows 10/11 x64 + Google Chrome 或 Microsoft Edge（程序自动查找）。无需安装 Python。

## 命令行模式

```
保卫鱼娘助手.exe --login                    # 打开浏览器手动登录
保卫鱼娘助手.exe --run --rounds 10          # 挂机 10 场
保卫鱼娘助手.exe --run --rounds 10 --headless   # 后台模式（不显示浏览器）
保卫鱼娘助手.exe --run --one-hit            # 秒杀模式（卡牌伤害直接击杀）
保卫鱼娘助手.exe --run --one-hit --one-hit-mode probability --one-hit-probability 50  # 50% 概率秒杀
保卫鱼娘助手.exe --run --one-hit --one-hit-mode multiplier --attack-multiplier 2  # 2 倍攻击力
保卫鱼娘助手.exe --run --one-hit --one-hit-mode fixed_attack --attack-fixed 100000  # 固定各卡基础攻击力
保卫鱼娘助手.exe --run --finish-fast --rounds 10  # 开局后自动收尾，正常完成 10 场
保卫鱼娘助手.exe --run --attack-speed-multiplier -2  # 攻速降到原速的 1/2
保卫鱼娘助手.exe --run --attack-interval 0.5  # 固定普攻间隔 0.5 个游戏秒
保卫鱼娘助手.exe --run --wind-probability 40 --wind-cd 1  # 所有风卡 40% 概率，共享 1 秒 CD
保卫鱼娘助手.exe --run --ice-probability-multiplier 2 --ice-cd 2 --repeat-ice --repeat-earth
保卫鱼娘助手.exe --run --no-hp              # 关闭自动回血
保卫鱼娘助手.exe --run --max-battle-minutes 5  # 单场最长监控 5 分钟
保卫鱼娘助手.exe --run --stop-stage 20      # 到第 20 关后自然结束
保卫鱼娘助手.exe --run --advance-stages 5   # 从起始关再推进 5 关后自然结束
保卫鱼娘助手.exe --selftest                 # 自检（driver / 浏览器可用性）
保卫鱼娘助手.exe --run --debug              # CLI 挂机并生成诊断文件
```

> **关于 CPU 占用**：游戏是 WebGL（PixiJS）画面，程序默认启用硬件加速，战斗中约占 **3~5% 整机 CPU**。
> `--headless` 后台模式下 Chrome 无法调用 GPU，会退化为软件渲染，CPU 会明显升高（约 50% 整机）——介意的话请用窗口模式挂机。

窗口程序没有控制台，命令行日志写入 exe 同级目录的 `run.log`。

雷/火/冰/风分别使用 `thunder` / `fire` / `ice` / `wind` 参数前缀，均支持
`--前缀-probability`、`--前缀-probability-multiplier` 和 `--前缀-cd`。
固定概率限制为 0–100%，概率倍率为 0–100 倍；风系 CD 为 0.5–180 秒，
其余为 0–180 秒；所有系都支持 `-1` 使用原生冷却。风系输入 0 自动修正到 0.5，
其余系输入 0 表示不加额外冷却；低于下限的其它数值也自动修正。攻速倍率限制为 -100–100，
负值绝对值不足 1 时归到 -1；固定间隔负值归到原生最低 0.2 秒。
输入越界会自动修正。时间单位均为游戏秒，不是现实秒；这些设置不改变整体游戏时钟。

## 从源码运行

```bash
python -m pip install playwright
python yu_gui.py            # 图形界面
python bot.py --run --rounds 1   # 命令行
```

需要系统 Python 3.11+（打包用的 GUI 依赖 tkinter，需完整版 Python）。打包脚本会自动安装
`playwright` 和 `pyinstaller`；不需要执行 `playwright install`，程序会复用本机 Chrome/Edge。

## 打包

```bat
打包exe.bat
```

产物：`保卫鱼娘自动挂机\保卫鱼娘助手.exe`。需要完整版 Python（自带 tkinter）。

仓库中的 `.github/workflows/build-windows.yml` 可手动触发，也会在推送 `v*` 标签时自动构建。
工作流验证代码、分别构建普通版/Debug 版，然后把两个 EXE 直接上传到 GitHub Release。
版本来自 `VERSION`，使用 `v1.1.0`、`v1.1.1` 这样的普通 Tag；发布新提交前更新 `VERSION`
及 `RELEASE_NOTES.md`，已有版本的 Tag 不移动。Actions 备份产物也只打包一层。
GitHub runner 无需安装 Chrome，运行时仍使用用户电脑上的 Chrome/Edge。

本地打包 Debug 版：在运行打包命令前设置 `GUARD_FISH_BUILD_FLAVOR=debug`，产物为
`保卫鱼娘助手-Debug.exe`。从源码启动可运行 `python yu_debug.py` 或 `python yu_gui.py --debug`。

Playwright 官方没有 PyInstaller hook，`yu_gui.spec` 里手动把 `site-packages/playwright/driver`（node.exe + cli.js，约 102MB）打进了包。

## 原理简述

- 直接打开游戏切片页 `douyu.com/pages/vibe-lab-act202606-game/mine?rid=<房间号>`，不依赖直播间入口
- 游戏接口全部在 `/japi/revenuenc/web/actgame/**`：`battleStart`（开战，消耗 1 次免费次数）→ `stageStart` → 战斗由页面引擎自动推进（`stageEventReport` 自动上报）→ `stageEnd` → `nextStage`（带技能选择）→ 循环至基地血量归零或用户设置的单场监控上限 → `receiveBox` 领宝箱
- 页内注入 fetch/XHR hook 实时抓取接口数据（状态展示 + 落盘），Python 侧用状态机驱动 DOM 点击
- 技能评分：全卡攻击/血量 > 全卡攻速 > 土系（主力）> 雷/火 > 冰/风；「绝技+1」因不使用绝技评为最低
- 付费识别：绝技/加速/刷新确认弹窗均含"送出礼物（N鱼翅）"字样 —— 自动化代码**从不点击**这些入口（连入口按钮本身也不点）

## 数据目录

默认存在 exe 同级：`config.json`（GUI 配置）、`chrome_profile/`（登录态）、`logs/`（抓包 + 战报 + 异常截图）。
exe 所在目录不可写（如装在 `Program Files`）时自动回退到 `%LOCALAPPDATA%\GuardFishBot`。

更新时把新版 EXE 放入原数据目录，保留 `config.json` 与 `chrome_profile/`；如果换目录，需将它们一同复制。
此前版本没有写过配置文件，因此首次升级到 v1.1.0 仍需填一次设置，之后会自动保存。
GUI 配置不覆盖 CLI 显式参数。
数字输入在失焦或按回车后应用到游戏；点击空白区域、说明文字或日志可失焦。复选框与模式选择即时应用。

## 单关耗时与 Debug 反馈

`进行中 t=...` 是约每 60 秒输出的状态日志，`t` 为本场监控时间；关卡号来自接口**响应**更新的
`window.__WM.stage`，由助手轮询读取。常规轮询间隔仍为 0.5 秒，处理技能或弹窗时会有短暂等待。

单关计时优先记录 `stageStart` 和 `stageEnd` 的响应观测时间，看到进入下一关后才确认前一关通过。
接口齐全时，选技能等关间等待不计入这对响应的间隔。缺少接口时标注切关估算；中途接管标注
仅观测到的时段；跨过多关、最后未完成的关卡不会伪造单关通关成绩。数值是客户端观测耗时，
包含网络/响应处理延迟，并非服务端给出的官方通关用时。

Debug 版开始挂机后生成 `logs/debug_时间戳.jsonl`，每次运行单独一个文件、逐条落盘。
每 15 秒及切关时采集引擎/卡牌/敌人/特效配置与计时字段；首次识别还保存相关方法源码，
以便分析整体速度、攻速、特效 CD 和概率。只读采集不修改游戏对象，不调用其方法，
不读取 Cookie 或 localStorage。v1.2.1 起还记录战斗相关的请求体、查询参数和响应的脱敏字段/数值，
包含结算 `stat` 内嵌 JSON；不保存认证/身份字段原文。若引擎未识别，文件也会记录结果。
完成一场并返回主界面后点「打开数据目录」，回传这份新的 Debug 文件即可。
旧 Debug 只有响应，不能用来判断请求中具体提交了哪些统计。分析见 [上报与每日任务记录](docs/report-notes.md)。
